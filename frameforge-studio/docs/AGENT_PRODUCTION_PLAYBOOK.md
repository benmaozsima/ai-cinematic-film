# Frameforge production playbook

Use this with the portal UI, including when operating with a smaller model. The portal stores every prompt, version, review, and edit decision; use the current film state instead of memory.

1. Read the film logline, approved screenplay, production bible, and shot list. For every shot, write down the required visible action and the exact spoken line. If the story promises an event, give it a shot where it can be seen.
2. Make identity and location references, then keyframes, then short video takes. Generate one shot at a time. Confirm that each reference is actually selected in the model request preview. Do not pay for another take until the prior job's status is known.
3. Watch each take from beginning to end. Record when the required action starts and ends. A prompt saying “runs” is not evidence of running. Reject or revise a take that omits an action, changes identity, or introduces a visual glitch.
4. For speech, use the exact approved line displayed by the portal. Compare what is heard to that line word by word. For silent video plus speech, approve both sources, run lip-sync, then check audio onset against the first mouth movement and look for accidental double dialogue. For native sound, do not layer a second copy of the same voice.
5. Mark quality checks individually when there is uncertainty. “Mark all passed” is only a shortcut after actually watching or listening. Leave a check pending if you cannot verify it. Approve only the take that met the script; choose that approved version in the cut.
6. In the connected cut, open “Screenplay-to-cut check.” Watch every transition and compare each visible action and spoken line to its row. Confirm sound mix, full duration, and the end beat. Fix only the failing asset, then repeat the cut review.
7. Export the approved film. Confirm the MP4 actually downloads, contains video and audio, has the intended duration and aspect ratio, and plays through to the final frame. Report any remaining uncertainty rather than describing the film as perfect.

For the Rosh Hashanah production, the first rejected mistake was a recorded line of “נו... יפה לי?” while the screenplay said “נו... איך אני נראית?”. The second was an apple take whose prompt mentioned running but whose motion did not show it. These are distinct failures: the first is a text contract violation; the second requires human visual judgment. Both must be checked before approval.
